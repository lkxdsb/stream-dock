# 抖音本地网站承接脚本设计说明

## 目标
做一个仅本地使用的网站，用来承接现有脚本 `douyin_fetch.py` 的能力。

用户流程：
1. 粘贴抖音分享文本或链接
2. 输入输出目录
3. 选择输出类型 `m4a / mp3 / mp4`
4. 点击开始
5. 页面显示执行日志与最终文件路径

## 范围

### 第一版包含
- 本地网站
- 单任务模式
- 前后端分离一点：后端 API + 前端页面
- 复用现有 `douyin_fetch.py`
- 日志显示
- 成功/失败状态显示

### 第一版不包含
- 多任务队列
- 批量下载
- 实时流式日志
- 系统目录弹窗选择器
- 部署到公网
- 账号体系

## 架构

### 后端
使用 FastAPI，提供：
- `GET /`：返回页面
- `POST /api/fetch`：接收请求参数并执行下载

后端不重复实现抓取逻辑，而是直接调用：
- `douyin_fetch.py`

这样可以最大化复用现有能力，减少重复维护。

### 前端
使用原生 HTML + CSS + JavaScript：
- 一个链接输入框
- 一个输出目录输入框
- 一个输出类型下拉框
- 一个提交按钮
- 一个日志区
- 一个结果区

页面风格以本地工具为主：清晰、克制、好读，不追求复杂组件。

## 为什么这样设计
1. 当前核心抓取逻辑已经在 `douyin_fetch.py` 中验证过。
2. 网站层只需要承接输入输出，不应该重写抓取逻辑。
3. 原生前端足够完成第一版需求，能明显降低复杂度。
4. FastAPI 适合本地快速起服务，也方便后续扩展接口。

## API 设计

### `POST /api/fetch`
请求体：
```json
{
  "link": "抖音分享文本或链接",
  "outputPath": "/absolute/path",
  "outputType": "mp3"
}
```

返回体：
```json
{
  "success": true,
  "stdout": "...",
  "stderr": "...",
  "outputPath": "/absolute/path/to/file.mp3"
}
```

失败时：
```json
{
  "success": false,
  "stdout": "...",
  "stderr": "...",
  "error": "..."
}
```

## 执行方式
后端通过子进程调用：
- 当前 Python 环境运行 `douyin_fetch.py`
- 捕获 stdout/stderr
- 将结果返回给前端

好处：
- 后端代码简单
- 不用重构现有脚本主流程
- 调试容易，和命令行结果一致

## UI 设计

### 页面结构
- 顶部标题：说明这是本地视频解析工具
- 表单区：输入链接、路径、格式
- 操作区：开始按钮
- 日志区：展示脚本输出
- 结果区：展示最终生成文件路径

### 视觉原则
- 以工具界面为主，不做营销风格
- 深浅对比清楚
- 日志区使用等宽字体
- 减少装饰，强调状态反馈

## 错误处理
需要覆盖这些情况：
- 链接为空
- 输出目录为空
- 输出类型非法
- 脚本执行失败
- 后端异常

前端要明确告诉用户失败原因，不只显示“失败”。

## 文件结构
建议新增：
- `app.py`：FastAPI 服务入口
- `templates/index.html`：页面模板
- `static/app.js`：前端交互逻辑
- `static/style.css`：页面样式

复用：
- `douyin_fetch.py`

## 启动方式
本地运行：
```bash
source $(conda info --base)/etc/profile.d/conda.sh
conda activate jj
uvicorn app:app --reload
```

访问：
- `http://127.0.0.1:8000`

## 结论
第一版网站最合理的实现，不是增加新的抓取复杂度，而是：
- 用本地页面承接参数输入
- 用 FastAPI 承接调用
- 继续复用已经验证过的 `douyin_fetch.py`

这样开发快、风险低、后续好扩展。
