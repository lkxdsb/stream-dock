# 抖音链接提取脚本设计说明

## 目标
做一个最小可用脚本，支持三个输入参数：

- `link`：抖音复制链接文本或直接视频链接
- `outputPath`：输出目录
- `outputType`：`m4a` / `mp3` / `mp4`

脚本目标不是承诺 100% 成功，而是在可访问内容范围内，用分层策略尽可能提高成功率。

## 设计原则

1. 入口简单，只有三个核心参数。
2. 优先走免登录路径。
3. 免登录失败后再尝试本机 Chrome 登录态。
4. 尽量复用真实浏览器播放链路，而不是只依赖静态页面源码。
5. 输出清晰日志，能解释失败原因。

## 核心流程

### 1. 解析输入
- 如果传入的是“抖音复制链接整段文本”，先用正则提取出 URL。
- 如果是短链，如 `https://v.douyin.com/.../`，允许浏览器自动跳转到真实视频页。
- 校验输出目录是否存在，不存在则创建。

### 2. 提取策略
按以下顺序依次尝试：

#### 策略 A：免登录浏览器抓流
使用 Playwright 打开链接，等待页面真实播放。

优先抓取：
- 独立音频流，例如 `media-audio-und-mp4a`

如果没有独立音频流，则退化为：
- 获取 `<video>` 当前真实播放地址 `currentSrc`
- 下载视频流后再抽取音频

这是当前第一版的主路径，因为实测对公开视频成功率更高。

#### 策略 B：Chrome 登录态兜底
如果策略 A 失败，则尝试读取本机 Chrome 的抖音 cookies：
- 用 `browser-cookie3` 获取 cookies
- 用 Playwright 带 cookie 打开页面
- 重复抓流流程

### 3. 输出策略
- `outputType = mp4`：直接保存视频文件
- `outputType = m4a`：
  - 如果拿到独立音频流，优先直接保存并封装为 m4a
  - 如果拿到视频流，则用 ffmpeg 抽取音频为 m4a
- `outputType = mp3`：
  - 如果拿到音频流或视频流，都统一用 ffmpeg 转 mp3

## 文件命名
- 默认使用页面标题作为基础文件名
- 替换非法文件名字符：`\\ / : * ? " < > |`
- 限制文件名长度，避免路径过长

## 错误处理
脚本需区分并输出这些失败原因：
- 未从输入中提取到链接
- 页面打开失败
- 页面未获取到媒体流
- 登录态兜底仍失败
- 下载失败
- ffmpeg 转换失败

## 技术选型
- Python 3.11+
- Playwright：真实浏览器播放与抓流
- requests：下载媒体文件
- browser-cookie3：读取 Chrome cookies
- ffmpeg：音视频转封装与转码

## 第一版范围

### 包含
- 命令行脚本
- 三个核心参数：`link` / `outputPath` / `outputType`
- 免登录抓流
- Chrome 登录态兜底
- 输出 m4a / mp3 / mp4
- 清晰日志

### 不包含
- 网页界面
- 批量下载
- Safari / 抖音桌面端登录态适配
- 多平台支持
- 任务历史记录

## 结构设计
建议文件：
- `douyin_fetch.py`：主脚本

第一版不急着拆太多文件，避免过度设计；等功能稳定后再考虑模块化。

## 测试思路
- 用已验证的两类样本测试：
  1. 有独立音频流的视频
  2. 只有带音轨视频流的视频
- 校验三种输出类型：`m4a` / `mp3` / `mp4`
- 校验无效链接时的报错

## 结论
第一版最佳实现不是追求“100% 必成”，而是：

- 先免登录
- 抓不到独立音频就抓视频流
- 再失败才走 Chrome 登录态
- 最后给出明确失败原因

这符合当前实测结果，也最贴近可长期维护的实现方式。
