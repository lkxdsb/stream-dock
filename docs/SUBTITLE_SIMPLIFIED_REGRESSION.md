# 简体中文字幕（2026-10-09）

原因：中文 ASR 配置 `language=zh` 不限定输出文字的简繁；此前项目直接将识别文本写出 SRT。
这不是 CSS 或字体问题。用户的实际字幕文件包含 188 个片段、约 5 分 20 秒，原文确为繁体。

## 修改

- 中文 faster-whisper/openai-whisper 识别后使用 OpenCC `t2s`，自动检测到中文时同样转换；默认中文 CLI 输出也在文件写出前转换。
- 保留片段时间轴，不改写英文、emoji 和数字；非中文识别不自动转换，避免影响日文等语言。
- 字幕工作台提供“转为简体中文”，适用于既有 ASR、OCR 或平台字幕；导入不自动改写，原文件不覆盖。
- 可导出或保存为任务新版本；异步转换时若发生编辑/切换文档，丢弃旧结果而不覆盖新编辑。
- 主依赖与 Python 3.11 锁文件加入 OpenCC，缺失时给出明确错误，不静默保留繁体。

## 真实验证

- 用户视频实际截取前 20 秒，真实 faster-whisper 转录产生 10 条简体 SRT，含“将就一辈子”“没有考虑过”等。
- 实际内置浏览器加载用户原 188 条字幕，点击转换，保存为任务字幕版本 2；原繁体 SRT 保留。
- 实际本地 API 导入/转换/导出 SRT、VTT、TXT，文件严格 UTF-8 回读后 188 条内容匹配；SRT/VTT 时间轴逐项相等。TXT 格式无时间轴，未声称保留时间信息。
- M6 自动浏览器回归实际点击按钮并下载导出文件，核对中文、emoji、英文和时间轴。
- 全量 Python 回归 455 passed、41 subtests passed。

本地证据：`report_figures/subtitle-simplified-live/` 下的原文备份、实际 ASR 片段、导出文件、验收 JSON 和内置浏览器截图。
本次只修复简繁输出，不宣称修复原有语音误识别或完成整段视频逐句准确性验收。

新部署需安装更新后的 requirements.txt；本地已安装 OpenCC 并实际重启服务。
